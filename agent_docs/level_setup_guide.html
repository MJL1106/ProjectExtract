Master checklist — dressing a fresh level, in order

  1. World Settings → GameMode Override = the playable GameMode BP BP_ExtractionGameMode (/Game/Core/Blueprints/Game)
  2. Place a PlayerStart in a neutral, enemy-free area
  3. Place BP_Companion (/Game/Core/Blueprints/AI/Companion) near the PlayerStart
  4. Place a NavMeshBoundsVolume covering everything playable (all floors), press P to confirm green coverage
  5. Block out geometry; make sure floors/ceilings block the Visibility collision channel
  6. Place enemies: drag BP_Enemy_Grunt / Rusher / Heavy / Sniper / Officer / Grenadier / Shotgun / Pistol (/Game/Core/Enemies/Blueprints) onto navmesh; set SquadId, assign PatrolRoute or leave as static guard; keep bIsolatedEncounter = false; author DeathLoot on keycard-carrier enemies
  7. Place PatrolRoute actors for moving guards (points on navmesh)
  8. Place ONE CoverSystem actor (AICoverSystem plugin) — cover auto-generates from the navmesh for enemies AND the companion. Rebuild navmesh after geometry changes; add ManualCoverPoints only where the generator misses a spot
  9. Place EnemySpawnZone boxes (3–5 per floor, hidden rooms/stairwells) and assign a DirectorConfig; optional building-wide EnemyDirectorScopeVolume
  10. Place TakedownVolume boxes around intended stealth-takedown pockets
  11. Place BreachableDoor BPs; set OpenAngle, and bStartsLocked + RequiredKeycardId for keycard doors
  12. Place LootContainer BPs; author Contents (ammo / keycards — keycard ids must match doors)
  13. Place ObjectiveMarkerActors; set Label + completion (CompletionRadius or RequiredKeycardId)
  14. Optionally place CompanionRoute + CompanionRouteTrigger for authored lead-the-way sequences
  15. Place BP_PhaseTrigger (/Game/Core/Enemies/AI) boxes at story beats to advance the mission phase (Infiltration → Objective → Extraction)
  16. Rebuild navmesh + lighting, PIE from the PlayerStart, walk the level with the Gameplay Debugger (' key)

0 · Level prerequisites

GameMode. Set World Settings → GameMode Override to BP_ExtractionGameMode (/Game/Core/Blueprints/Game). Don't rely on the C++ default — the C++ class points at a legacy pawn; the BP override supplies the real player pawn (its Default Pawn Class is already set to BP_ExtractionCharacter, which despite the legacy name is the live player pawn).

NavMesh. One NavMeshBoundsVolume scaled over the entire playable space, all floors. This is the single most common "AI does nothing" cause: the companion's follow/combat/revive, enemy patrols, cover moves, and director spawns ALL silently fail off-navmesh. Press P in the viewport — every walkable surface should be green.

Visibility channel. Floors and ceilings must block the Visibility trace channel, or enemies will detect the player through floors and the director will refuse/misjudge spawn points.

Placing the C++ actors. CompanionRoute, CompanionRouteTrigger, ObjectiveMarkerActor, TakedownVolume, PatrolRoute, EnemySpawnZone and EnemyDirectorScopeVolume have no Blueprint wrappers — place them by typing the class name into the Place Actors panel search (Window → Place Actors) and dragging into the viewport.

Companion. Drag BP_Companion (/Game/Core/Blueprints/AI/Companion) into the level near the PlayerStart. It is not auto-spawned by the GameMode. Its AI controller, behaviour tree and tuning are already wired on the BP — nothing to set per level.

1 · Companion + ping control works out of the box

The ping component lives on the player pawn; nothing to place. Pinging line-traces from the camera (60 m) and picks, in priority order:

Ping hit → 1. Breachable door → companion breaches (style from current mode) 2. Lootable container → companion goes and loots it 3. Eligible enemy → takedown prompt (knife / shoot)

Modes (cycled with X): Normal / Combat / Stealth. The active mode picks the breach style automatically: Combat → Loud kickdown, Normal → Tactical, Stealth → Quiet. Mode also drives the companion's movement stance and engagement rules — there is no per-level mode config; if a mission should start in Stealth, call SetMode from the Level Blueprint at BeginPlay.

2 · Authored companion routes works out of the box

For "companion takes the lead" set pieces (intro rooftop, cleared-room walkthroughs).

Place: CompanionRoute

Author its Waypoints array — each waypoint is a draggable 3D widget in the viewport. Per waypoint:

PropertyDefaultWhat it does
Location—Drag the widget in the viewport
StanceRelaxedRelaxed / Alert / Crouch for the leg into this point
bWaitForPlayer + WaitForPlayerRadiusoffCompanion holds here until the player is within the radius
DwellSeconds0Pause at the point
SpeedOverride0 (off)Per-leg speed
bOverrideAim + AimTargetLocaloffForce a look direction at the point

Route-level: EndBehavior (ReturnToFollow / HoldAtFinal), bInterruptibleByCombat, DefaultStance, WaypointAcceptanceRadius (60), MaxWaitForPlayerSeconds (15 — hang safety).

Trigger: CompanionRouteTrigger

A box volume. Assign its Route to your placed CompanionRoute (eyedropper), bOneShot = true by default. Player walks in → route starts. Alternatively call StartRoute on the companion's AI controller from the Level Blueprint or a Sequencer event.

3 · Doors + breaching Loud/Tactical/Quiet shipped

Place: BP_BreachableDoor (/Game/Core/Blueprints/World)

PropertyDefaultWhat it does
OpenAngle-90Swing angle in degrees (sign = direction). Set per door
OpenDuration0.8Seconds to swing (quiet open; loud is montage-timed)
bStartsLockedfalseLocked doors need a keycard and are NOT offered to companion breach
RequiredKeycardIdNoneFName; must exactly match a loot container's keycard id
BreachReachGap / PostBreachEnterDepth / PostBreachLateralOffset25 / 250 / 170Companion stand-off and post-breach entry points — only touch if a doorway is unusually tight
Rotate the whole actor, never the leaf. The swing is computed from the door leaf's world yaw at BeginPlay. Place/rotate the root actor freely; if you rotate or offset the internal LeafPivot the swing breaks.

How the player uses it: ping the door → companion breaches in the current mode's style (Loud kickdown / Tactical kick-then-fall-back / Quiet handle-open). Locked doors: player collects the keycard — from a loot container or off a killed enemy carrying it in its DeathLoot (see §4) — then Interact (E) on the door to unlock.

4 · Loot containers + keycards shipped

Place: BP_LootContainer (/Game/Core/Blueprints/World)

Author the Contents array per placed container. Each entry (FLootGrant):

TypeFieldsResult when looted
AmmoAmmoCategory (weapon type), AmmoAmount (30)Added to the player if it matches their weapon category — even when the companion loots it
KeycardKeycardId (FName)Recorded in the mission inventory for the rest of the level

bLooted = true makes a container pre-emptied set dressing.

Keycard flow — id matching is your whole job

LootContainer.Contents[KeycardId = "Keycard_Lab"] ── or ── Enemy.DeathLoot[KeycardId = "Keycard_Lab"] │ (player interacts, or player pings → companion loots) (kill → drops a pickup, loot it) ▼ Mission inventory records "Keycard_Lab" (world-lifetime, no UI to place) │ │ ▼ ▼ BreachableDoor.RequiredKeycardId ObjectiveMarkerActor.RequiredKeycardId = "Keycard_Lab" → E unlocks = "Keycard_Lab" → objective completes
Keep keycard ids as a naming convention (Keycard_<Area>) and spell them identically in the container, the door, and any objective. A typo fails silently.

Enemy keycard carriers — "kill the officer with the keycard"

Instead of (or as well as) a container, any placed enemy can carry the keycard:

  1. Select the enemy → Details → Enemy|Loot → DeathLoot → add an entry: Type = Keycard, KeycardId = Keycard_Lab (ammo entries work too).
  2. On death it drops a guaranteed physical pickup (BP_LootPickup (/Game/Core/Blueprints/World)) beside the corpse — spawn logic picks a clear spot so the ragdoll can't bury it, and ground-snaps on stairs/ledges.
  3. Collect with E or ping it for the companion — same grant path as a container, so the matching locked door and any objective with that RequiredKeycardId react identically.

The pickup never despawns (mission-critical), and its mesh is currently a placeholder rifle mag on BP_LootPickup — swap when a proper keycard mesh is imported. LootPickupClass is already assigned on all 8 enemy BPs; nothing to set per level beyond the DeathLoot entry.

5 · Objectives + waypoint markers shipped

Place: ObjectiveMarkerActor

PropertyDefaultWhat it does
ObjectiveIdactor nameUnique id (only matters if scripting against it)
Label—Text shown on the HUD marker
bActivateOnBeginPlaytrueOff = activate later from Level BP (for chained objectives)
CompletionRadius0 (off)Completes when the player enters this radius ("go here" objectives)
RequiredKeycardIdNoneCompletes when that keycard is looted ("find the keycard" objectives)
bToastOnCompletetrueOn-screen completion toast

The HUD distance marker (edge-clamped icon + metres) renders automatically for every active objective — no per-objective UI work.

Chaining: place objective 2 with bActivateOnBeginPlay = false, then in the Level Blueprint bind objective 1's OnObjectiveCompleted → call Activate on objective 2. That gives you "reach the lab → find the keycard → extract" as three placed actors and two BP wires.

6 · Takedown pockets shipped

Place: TakedownVolume

A plain box — scale it over each area where silent takedowns should be possible. No properties to configure. It does two things:

1. Enables takedowns. An enemy is ping-takedown-eligible only while Unaware AND standing inside a TakedownVolume. Enemies sharing one volume can be taken down as a synced pair (player takes one, companion the other). After pinging, confirm with the knife key (hand-to-hand) or shoot key (companion headshots; if you shoot and miss, the companion assist-headshots after ~1.5 s). Suppressor logic is automatic from the equipped weapons — nothing level-side.

2. Muffles awareness. Enemies inside the volume ignore distant gunfire/footstep/squad stimuli (sprint footsteps and Loud events still wake them), so a takedown pocket stays quiet while a fight happens elsewhere.

Place one volume per intended stealth pocket (a pair of guards at a doorway, a lone sentry on a balcony). Don't blanket the whole level — the muffle side-effect would deafen everyone.

7 · Enemies + patrols shipped

Place: archetype BPs

Drag the archetype Blueprint into the level — each already carries its DataAsset (stats, weapon, perception, behaviour subtree), mesh and animation setup: BP_Enemy_Grunt / Rusher / Heavy / Sniper / Officer / Grenadier / Shotgun / Pistol (/Game/Core/Enemies/Blueprints)

Per placed enemy (Details panel)

PropertySet it to
SquadIdSame FName for enemies that should share sightings, flank together and focus-fire (e.g. Squad_Lobby). Leave None for loners
PatrolRouteA placed PatrolRoute actor for moving guards. Unset = static guard at spawn (or set bOverrideGuardPost + GuardPostOverride for an explicit post)
bIsolatedEncounterfalse (the default) for real levels. True is a test-gym flag that stops the enemy waking the director
DeathLootOptional loot this enemy is carrying (same entries as a container: ammo or keycard). On death it drops as a guaranteed physical pickup next to the corpse — player Interact or companion ping-loot collects it. Enables "kill the officer carrying the keycard" objectives: pair the KeycardId with a locked door and (optionally) an objective marker's RequiredKeycardId

Every enemy must stand on navmesh, not embedded in cover meshes or wall edges.

Place: PatrolRoute

Points = an array of draggable 3D widgets (3+ points, all on navmesh). bLoop true = circuit, false = ping-pong. WaitAtPointSeconds (2) = pause at each point.

8 · Enemy director + spawn zones shipped

The director (reinforcement pacing) is a world subsystem — always present, but it does nothing until the level feeds it spawn zones, and it only wakes once the fight goes Loud. Placed enemies handle stealth; the director handles sustained combat.

Place: EnemySpawnZone

Box volumes — the only source of reinforcement spawns. 3–5 per floor, in service rooms / stairwells / back corridors, 15–45 m from expected fights, out of player sightlines, on navmesh. Spawns are rejected if visible to the player, outside the distance band, or off-navmesh.

PropertyWhat it does
AreaTagOrganizational label
ActivePhasesRestrict the zone to mission phases (empty = all)
DirectorConfigAssign the pacing DataAsset DA_DirectorConfig (/Game/Core/Enemies/AI/Data) on at least one zone (first registered wins)
A DirectorConfig phase with an empty Compositions list spawns nothing even with zones placed — and placed enemies count toward MaxAlive, so a floor dense with placed enemies can starve reinforcements. That's a tuning lever, not a bug.

Mission phases

Place BP_PhaseTrigger (/Game/Core/Enemies/AI) boxes at story beats — each advances the director to its configured phase when the player walks in (fire-once): Infiltration (approach) → Objective (the point of interest) → Extraction (the way out). Each phase has its own intensity ceiling / cadence / max-alive / composition in the DirectorConfig.

Optional: EnemyDirectorScopeVolume

One box around the whole playable building (full height, all floors). Without it the director considers the whole world — fine for a single-building level, needed once maps have out-of-play space.

9 · Cover system auto-generated

Place: CoverSystem (one per level — AICoverSystem plugin, via Place Actors search)

Cover is generated automatically from the navmesh and level geometry — every desk, crate, pillar, waist-wall and corner becomes usable cover for enemies AND the companion (crouch/stand height, peek sides and corner leans are derived from the geometry). One CoverSystem actor per level is the whole setup; generation runs when navigation builds and re-runs when it rebuilds.

What this means for level design: you don't author cover — you author geometry. Chest-high blockers, doorway frames and corners near expected fight spaces automatically become the AI's cover vocabulary. If a room feels like it has cover to you as a player, the AI sees it too.

Optional: ManualCoverPoint

Hand-placed single cover point, injected into the same generated pool — only for spots the generator misses or ignores (unusual meshes, props with odd collision). Not needed in normal dressing.

Checking coverage: after building navmesh, the CoverSystem actor's debug drawing shows generated cover points. If a blocker isn't producing cover, check its collision blocks the navmesh (the object must carve/affect nav) and rebuild navigation.
Transitional: two behaviours (sniper nesting, enemy fallback-to-cover) still read the old hand-placed cover-slot actors until the legacy system is deleted. If a level features snipers, drop a few BP_CoverSlot_StandFire (/Game/Core/Blueprints/AI/Companion/Cover) at intended nest spots; otherwise ignore the old slot BPs entirely.

10 · Ammo drops data-only

Nothing to place. Killed enemies roll a drop chance from the drop-table DataAsset DA_AmmoDropTable (/Game/Core/Data) assigned once on the base enemy BP (default 40% chance, 15–45 rounds, per weapon category; pickups despawn after 60 s). Pickups only grant if their category matches the player's weapon. Room ammo comes from LootContainers (§4). If drops don't appear in a new level, check the base enemy BP still has the drop table and per-category PickupClass assigned — it's shared config, not per-level.

11 · Down-but-not-out / revive shipped

Nothing to place. When the player drops, the companion breaks off, paths in and revives (threat-gated: it clears nearby threats first, goes desperate as the bleed-out timer runs down). The only level requirement is the one you've already met: navmesh coverage so the companion can reach the player anywhere they can go — including crawl-reachable spots (the player can crawl while downed).
