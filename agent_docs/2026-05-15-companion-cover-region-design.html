Companion Cover Region — Design Spec

Date: 2026-05-15 · Branch: AI-Companion-Prototype · Scope: A + B + C (cover-switching D deferred)

Context

The companion currently snaps to a single point-based AICoverSlot, sits there, peeks over, and only leaves when the target dies. Reads as static. This pass turns the slot into a designer-authored region, lets the companion shift positions within it, adds corner-peek as a step-out action for tall cover, and chains stand-up-fire into walk-fire-to-new-position transitions for visual polish.

Scope

Incover region (A), reposition / crouch-walk along cover (B), corner peek with continuous walk-and-shoot (C).

Outcover-switching triggers between separate slots (D — separate brainstorm), lean-on-wall idle montage (no anim authored yet — placeholder is stand-against-wall), crouch-corner-peek (not authored).

Cover region data model

AICoverSlot remains a single actor. Designer drags the existing UBoxComponent to define a linear region; the right-axis extent (perpendicular to slot forward, along the cover face) becomes the line length. Other extents are visual only.

New / changed fields

  • Height — existing ECoverHeight::Stand / Crouch, no semantic change.
  • bIsPeekableCornerStart — designer-set bool, true if the line's leftmost endpoint is an exposed corner (e.g. side of a car) where corner-peek is allowed.
  • bIsPeekableCornerEnd — same for rightmost endpoint.
  • CoverLineHalfLength — derived from the UBoxComponent right-axis extent at PostInitializeComponents. Designer doesn't edit this directly; they drag the box.

Helpers

  • FVector GetSubSlotLocation(int32 Index) const — returns world position of a sub-slot.
  • int32 GetSubSlotCount() const — endpoints + midpoints every ~1m (designer-tunable spacing constant).
  • bool IsSubSlotPeekableCorner(int32 Index) const — true only for endpoints flagged peek-able.
  • bool CanStandFireOver() const — replaces CanStandFireFrom(); true for Crouch cover, false for Stand. Same behaviour as today, renamed for clarity.

Sub-slot system

Discrete sub-slots are computed at runtime from line length. Always includes both endpoints; midpoints inserted every ~1m. A 3m line → 4 sub-slots; a 0.5m line → 2 sub-slots (just endpoints); a 0m line (legacy point-slot) → 1 sub-slot at origin (backwards-compatible).

Claim: the whole line is claimed by one companion at a time. No intra-line sharing.

Locomotion between sub-slots: direct lateral interp along the line vector (cover lines are straight by construction — no navmesh pathfind needed). Speed driven by walk/crouch-walk locomotion blendspace.

Posture

Height-driven from existing ECoverHeight:

  • Crouch cover → companion crouches in cover region. Uses existing crouch blendspace for idle and lateral movement.
  • Stand cover → companion stands. Cover-idle placeholder is stand-against-wall using existing stand-idle (lean-on-wall montage is future polish).

Picker matrix

Extends the existing peek-action picker. Available actions depend on cover type + current sub-slot.

Cover / positionPicker actions
Crouch cover (any sub-slot) StandUp, StandUpAndReposition, Quick, Reposition, Hold
Stand cover — midpoint sub-slot Reposition, Hold (no fire action available)
Stand cover — peek-able endpoint CornerPeek, Reposition, Hold

Picker reuses existing weight-driven roll, consecutive-Hold cap, suppression and low-health bias. Action weights become per-cover-type tunables on the BT task.

Per-action behaviour

StandUp (existing, unchanged)

Companion stands at current sub-slot, fires randomised burst, drops back to crouch at same sub-slot.

StandUpAndReposition (new, Crouch cover only)

Companion stands at current sub-slot, fires briefly, then begins lateral walk-while-firing toward a chosen other sub-slot. Continues firing through the transit (companion is standing, muzzle is over cover line). On arrival, stops firing and crouches at destination.

Low-weight roll by default (15-25%) — most stand-fires stay put. Designer-tunable.

Burst-end vs arrival race: if burst timer expires mid-transit, stops firing, continues walking silent, crouches on arrival. If arrival happens before burst end, stops firing on crouch (can't fire over cover while crouched).

Quick (existing, unchanged)

Short burst at current sub-slot. Crouch cover only (Stand cover has no fire option from midpoints; peek-able endpoints use CornerPeek instead).

Reposition (new, both cover types)

Silent lateral move to another sub-slot along the line. Crouch cover: uses crouch-walk blendspace. Stand cover: uses stand side-step. No firing during transit (companion is hidden behind cover the whole time). Cooldown-gated like the existing peek picker.

Hold (existing, unchanged)

Skip this cycle, reset cooldown. Consecutive-Hold cap applies as today.

CornerPeek (new, Stand cover peek-able endpoint only)

Companion strafes out past the cover edge (designer-tunable distance, default ~80cm in the slot's right or left direction depending on which endpoint), entering open ground. Begins firing the moment it clears cover. Continues firing through step-out → apex → step-back loop. Stops firing the moment the cover wall blocks LoS to target on the way back. Settles at endpoint, returns to stand-against-wall idle.

Suppression abort: if companion takes damage during corner-peek, retreat fires immediately (cancel forward motion, walk back to cover, stop firing once wall blocks LoS).

Burst duration applies as today; companion can return to cover early if burst expires before the apex.

EQS rejection rule

The cover-finding EQS scoring rejects Stand cover slots where neither endpoint is peek-able. These slots are hide-only and offer no firing solution. Designer can still author them (e.g. for stealth retreat in a future feature), but the companion won't claim them for combat.

Crouch cover is always accepted (fire-over works from any sub-slot, peek-able endpoints just add optional alternatives).

Triggers — sub-slot position picker

The choice of WHICH sub-slot the companion sits at is driven by:

  • LoS-driven (primary) — if current sub-slot loses LoS to combat target, evaluate other sub-slots, pick one with LoS. Same logic as today, scoped per sub-slot instead of per slot.
  • Periodic randomised cadence (secondary) — every 8-15s, low probability, if not currently firing and not suppressed, roll a Reposition action.
  • Locked out during suppression (recent damage) and active firing.

Animation integration

Uses existing player-shared assets:

  • Crouch blendspace — for crouched idle and crouch-walk along Crouch cover.
  • Stand walk blendspace — for stand side-step along Stand cover and CornerPeek step-out / step-back.
  • AimOffset blendspace — when authored, drives gun direction during fire. Still missing — see open question below.

No new montages required for this pass. Future polish (post A+B+C):

  • Lean-on-wall idle montage for Stand cover (replaces stand-idle placeholder).
  • Cover-lean-fire montage (for in-place corner peek without step-out).
  • Dedicated crouch-corner-peek montage (currently skipped — Crouch cover endpoints just stand-up-fire over).

Migration

Existing slot assets keep their Height enum unchanged. New fields default to:

  • bIsPeekableCornerStart = false
  • bIsPeekableCornerEnd = false
  • UBoxComponent extent unchanged from authored value (legacy slots will compute a small line length from their existing box; if extent is ~0 they collapse to 1 sub-slot at origin — same behaviour as today).

Designer opts in by:

  1. Dragging the box to add line length along the slot's right axis.
  2. Ticking bIsPeekableCornerStart / End for endpoints that expose open ground.
  3. Optionally tuning per-slot picker weights on the BT task (instance properties).

CanStandFireFrom() renamed to CanStandFireOver() — call-site update in BTTask_CompanionCombat only.

Open implementation questions

  • AimOffset BlendSpace authoring — gun direction during fire depends on this being present. Functionally bullets land regardless (weapon traces toward AimTarget), but visually the gun stays in its hand pose without it. Not a blocker for this pass; visual fidelity improves once authored.
  • Mid-CornerPeek LoS interruption — if an obstacle (e.g. a teammate) crosses the companion's LoS during the apex, should it abort? Current proposal: continue firing through brief blips (LosBlockedAccum already handles this for open-engage). Reuse same threshold.
  • StandUpAndReposition target sub-slot picking — pick adjacent sub-slot only (one step away), or pick any sub-slot on the line? Adjacent is simpler and shorter transit; "any" allows more dramatic moves. Recommend adjacent-only for prototype.
