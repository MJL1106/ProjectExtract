Objectives, Director, Waves & Loot

How to author the next section of the level: what the player is told to do, what the director throws at them, and what they find in the crates. Property names are verbatim from the Details panel; every number quoted is read from the live asset.

The director and the objective flow are independent. The flow does not spawn enemies, and the director does not know what the objective is. They meet in exactly two places: a phase trigger telling the director the mission moved on, and a wave request fired from an objective beat.

1 · Objectives — the two ways

A · ObjectiveMarkerActor data-only, use this for new content

Drop-in actor that registers a waypoint at its own location and can retire itself. This is the route for the next part of the level — no code, no C++ enum entry.

PropertyMeaningDefault
ObjectiveIdUnique id. Registering the same id twice replaces the first.actor's own name if left None
LabelShort line shown next to the icon and in the objective panel.empty
bActivateOnBeginPlayOff = the marker stays dark until something calls Activate().true
CompletionRadiusCompletes when the player gets within this many cm. 0 = disabled.0
RequiredKeycardIdCompletes when the mission inventory records that keycard. None = disabled.None
bToastOnCompleteRaise the "Objective complete" HUD toast.true

Set neither completion criterion and the marker is permanent until something destroys the actor or calls Deactivate(). OnObjectiveCompleted fires after the marker has already removed itself, so a handler can immediately activate the next one — including under the same id.

Chaining pattern. Place N markers, all with bActivateOnBeginPlay off except the first. Bind each one's OnObjectiveCompleted to the next one's Activate in the Level Blueprint. That is a whole objective chain with no C++.

B · ALevelObjectiveFlow step list is a C++ enum

One placed actor that runs the shipped level's beat sequence, listening to doors, routes, enemy deaths, loot and the extraction actors. It owns a single primary objective marker at a time and re-points it as the step advances.

Adding a genuinely new scripted beat to this actor is a code change — the steps and the events that drive them are fixed enums (ELevelObjectiveStep / ELevelObjectiveEvent). For the next section of the level, prefer A unless you want the checkpoint/fast-forward machinery, which only the flow has.

The shipped chain, in order. Each arrow is the event that advances it.

Two shipped patterns worth copying.

  • Area-anchored marker. Room1AreaLocation pins the "clear the room" marker to a fixed spot instead of chasing whichever enemy is still alive. Left at zero it auto-computes the spawn-time centroid of Room1Enemies.
  • Optional objective. SupplyCrates drives a second, text-only objective — it appears in the HUD panel with no world billboard and no off-screen indicator, and re-points to the nearest unlooted crate as you empty them. That "text-only" behaviour is the bShowWorldMarker = false flag on the subsystem call.

Marker anatomy (any route)

FieldMeaning

bShowWorldMarkerFalse = HUD text only, no billboard, no edge indicator. Use for optional objectives.

3 · Authoring the next objective

Say the next beat is "reach the server room, plant the device, hold, then leave by the north stair."

Place the objective chain
  1. Place Actors → search "ObjectiveMarkerActor" → drag to the server-room door
  2. Details → Objective → ObjectiveId → Obj_ReachServerRoom
  3. Details → Objective → Label → "Reach the server room"
  4. Details → Objective|Completion → CompletionRadius → 400.0
  5. Duplicate it to the device position; set ObjectiveId = Obj_PlantDevice, Label = "Plant the device", bActivateOnBeginPlay → false
  6. Level Blueprint → bind Obj_ReachServerRoom.OnObjectiveCompleted → Obj_PlantDevice.Activate
Arm the hold
  1. Place an ExtractionTargetActor at the device
  2. Details → ExtractionTarget|Objectives → ReachObjectiveId / DefenceObjectiveId → your own ids
  3. Details → ExtractionTarget|Wave → WaveRequest → fill per §7
  4. Details → ExtractionTarget|Wave → CompletionAction → UnlockExit
  5. Details → ExtractionTarget|Wave → LiftGateTarget → the north-stair gate actor

That gives you: waypoint → waypoint → interact → defence wave → gate unlocks, with no code. The ExtractionTargetActor registers its own reach and defence objectives, so you do not need marker actors for those two.

4 · Director — arming the next phase

When it does anything at all

The director is asleep until global alert reaches Loud — an enemy confirming combat, an alarm, or body discovery escalating. Before that, everything the player meets is a placed enemy. Stealth content is authored, not directed.

Once loud it ticks once a second and asks: is tension under the phase ceiling, has the cadence elapsed, is there alive-cap headroom, is there a legal zone. All four must pass.

Tension, and why kills pause spawning

Tension rises with kills, player damage taken, and each engaged enemy near the player; it decays every second. Cross PeakTensionThreshold and the director stops adding squads. Fall below ReliefEntryThreshold and it waits out ReliefDuration before building again. That is the sawtooth — hard fight, then quiet. Turning up TensionPerKill makes fights shorter.

Phases

One global phase at a time: Infiltration → Objective → Extraction. Not per floor, not per room. Each phase has its own ceiling, cadence, alive cap and squad list.

Advance the phase
  1. Place Actors → search "BP_PhaseTrigger" → drag into the level (/Game/Core/Enemies/AI)
  2. Scale the box across the whole doorway/corridor the player must pass
  3. Set its target phase in the Details panel
  4. File → Save Current Level

Advancing the phase forces the director back to Build, so the new phase can start applying pressure as soon as cadence and the alive cap allow. Put triggers on story beats, not floor changes.

Scope

EnemyDirectorScopeVolume limits what the director counts and where it can spawn. With none placed it sees the whole world — which is why the test gym has one, or the gym's 40-odd parked enemies would fill every alive cap.

Multiple enabled scopes act as one combined union, not as separate per-floor brains. Scale one box over the whole building, Z tall enough to include every floor, stairwell and spawn room. There is no runtime enable/disable, so do not try to use scopes as floor states — use ActivePhases on the zones instead.

5 · Spawn zones

EnemySpawnZone is a box the director pulls spawn points from.

PropertyUse
AreaTagLabel for you and the logs. No gameplay effect.
ActivePhasesWhich phases may use this zone. Empty = all phases. This is your per-floor / per-route control.
DirectorConfigPushed to the world director on registration if none is set yet. First zone to register wins — assign the same asset on all of them.
bWaveEligibleFinite waves only. Turn off for zones the player can watch from the fight room — the hidden-check treats glass as an occluder, so a zone behind a window passes the test and then pops enemies in full view.
WaveScoreBiasFinite waves only. Positive = preferred. Lets one zone be the majority spawner without becoming the only one.

A zone is rejected if…

  • it is not active for the current phase
  • it is outside the active scope volume
  • the nearest point in the box is closer than SpawnDistanceMin (live: 1500)
  • it is farther than SpawnDistanceMax (live: 4500)
  • the zone origin is visible from the player's viewpoint
  • any of the first 3 sample spawn points are visible
  • the origin will not project to navmesh

Placement rules

  • 15–45 m from the likely fight space. A perfect spawn room 60 m away is invisible to the director.
  • At least one wall or corner between the fight and the zone.
  • Service rooms, stair landings, back corridors, security offices, loading bays — not the main room.
  • Big enough for the largest squad in that phase; sized so the box does not spill into walls or props.
  • Reachable. A spawn closet still needs a door-sized nav path out.
  • Floors and ceilings must block Visibility, or cross-floor sightline checks behave strangely.
  • 3–5 zones per floor or major wing; 10–14 across a three-floor building.

6 · Choosing what spawns

Squad selection is per phase, from that phase's Compositions list on the DirectorConfigData asset.

  1. Compositions whose total member count will not fit under the phase's MaxAlive headroom are dropped.
  2. One of the survivors is chosen by weighted roll.
  3. A legal zone is picked and the squad spawns spread across the box, grouped as a squad and seeded with the player's last known position.

Weight is relative, not a percentage. 2.0 is twice as likely as 1.0. MaxAlive counts placed enemies too — put 8 living guards inside the scope with an Infiltration cap of 8 and the director cannot spawn anything until some die.

7 · Waves

A wave is a finite, scripted assault: N squads, spawned on a cadence, and it is complete only when all N have spawned and every member is dead. That is the difference from the ambient director, which never ends. Use waves for holdouts, defences and set-piece pushes.

The wave request

FieldMeaningDefault
WaveIdName it. Comes back in the completed/blocked events and the logs.None
TargetSquadsHow many squads the wave will send in total.4
MissionPhaseWhich phase block the compositions come from, for the duration of the wave.Objective
ConfigOverrideUse a different DirectorConfigData just for this wave. Wave config beats punishment beats base.null
bAutoEngageSquads spawn straight into combat on the player. Off = they spawn Searching and must find the fight themselves.true
SpawnCadenceOverrideSeconds between wave squads. 0 = use the phase cadence — usually too slow for a scripted assault.0
FirstSquadDelaySecondsDelay before squad one. Without this, the cadence gate applies to the first squad too and a 25 s cadence opens the wave with 25 s of silence.2.0
GuaranteedSquadsPin a named composition to a squad slot (1-based). Bypasses both the weighted roll and the MaxAlive fit filter.empty
BlockedWarningSecondsHow long the wave may be starved before it warns.30
Guaranteed squads are how you get a set piece. Composition choice is otherwise pure weighted RNG, so the Heavy push only ever showed up on a lucky roll. Pin {SquadNumber: 4, CompositionName: "HeavyPush"} and the wave always closes on the Heavy.

Firing one

RouteWhen
ExtractionTargetActor — its own WaveRequestDefault. Player interacts ("Begin Extraction"), wave runs, CompletionAction fires. Set bExternalTriggerOnly when another actor owns the trigger beat (the VIP rescue) — mesh hides, interaction disables, wave starts only via code.
ALevelObjectiveFlow — its ExtractionWaveOnly used when there is no ExtractionTarget wired. With one present the target's request wins, so the config never lives in two places.
Blueprint → StartWave on the director subsystemAnything bespoke. Refuses if another wave is already active.

Completion action

UnlockExitUnlocks the wired LiftGateTarget / LiftGate. The normal choice.
CompleteLevelEnds the level outright.
BroadcastOnlyFires the event and nothing else — you handle it in Blueprint.

Recipe — a three-stage holdout

  1. WaveId → Wave_ServerRoomHold
  2. TargetSquads → 6
  3. MissionPhase → Extraction (borrows the hardest composition list)
  4. FirstSquadDelaySeconds → 4.0 (a beat to take cover)
  5. SpawnCadenceOverride → 10.0 (phase cadence of 15 s is too slack for a holdout)
  6. bAutoEngage → true
  7. GuaranteedSquads → add {SquadNumber 1, "Grunts"}, {SquadNumber 4, "Rush"}, {SquadNumber 6, "HeavyPush"}
  8. Turn bWaveEligible off on any zone visible from the hold position
  9. Set WaveScoreBias to 2.0 on the two zones you want most of the pressure coming from

That reads as: soft opening, rushers at the midpoint, Heavy to close — with the RNG only deciding squads 2, 3 and 5.

Squads 2, 3 and 5 still respect MaxAlive. Six squads at ~4 members against a cap of 20 means the wave will stall mid-way if the player is not killing. That stall is intended pacing, not a bug — but if the wave must finish on a timer, raise MaxAlive in the ConfigOverride rather than lowering the squad count.

8 · Loot containers

BP_LootContainer (/Game/Core/Blueprints/World) is an invisible box you drape over an existing drawer, table, shelf or locker. The world geometry is the visual — the actor carries no mesh. One container = one search = everything in Contents granted at once, always to the player, even when the companion is the one who looted it.

PropertyMeaning
ContentsArray of grants. Authored per placed instance.
InteractPromptHUD prompt while looking into the volume. Default "Search".
bLootedTick on a placed instance to start pre-emptied — set dressing that reads as already searched.
InteractVolumeScale it over the drawer/shelf, not the whole room.
OnOpenedBlueprint event — play the drawer slide and the SFX here.

Grant types

TypeFieldsNotes
AmmoAmmoCategory, AmmoAmount (default 30)Category must match the recipient's current weapon type or nothing is granted. Rifle ammo in a pistol level is a dead crate.
KeycardKeycardIdMust match the door's RequiredKeycardId exactly. This is the whole job — a typo is a soft-lock.
StimStimCount (default 1)Clamped by the player's consumable capacity — over-stocking a crate silently wastes the surplus.
Place a supply crate
  1. Place Actors → search "BP_LootContainer" → drag onto the shelf
  2. Scale InteractVolume to cover the shelf face the player will look at
  3. Details → Loot → Contents → + → Type = Ammo, AmmoCategory = Rifle, AmmoAmount = 60
  4. Details → Loot → Contents → + → Type = Stim, StimCount = 1
  5. Details → Loot → InteractPrompt → "Search supplies"

9 · The assault-rifle case

BP_WeaponCase_AssaultRifle (/Game/Core/Blueprints/World) is the open foam case whose cutouts hold real pickup actors — not a loot volume. It authors in two tiers:

  • SlotDefinitions — every cutout this case type has. Authored once on the Blueprint. Editing it changes every placed case.
  • FilledSlots — which of those cutouts this placed case actually holds. A dropdown of the slot ids. This is the per-instance knob.

In the editor the filled slots show preview meshes; on BeginPlay the previews are destroyed and the real pickups spawn attached to the same socket.

Note the case offers the long suppressor, not the short one, and offers no holosight — those are choices in SlotDefinitions, not limits of the system.

Decide what a placed case contains
  1. Select the case in the level
  2. Details → Case → FilledSlots → + → pick a slot id from the dropdown
  3. Repeat per item. Duplicates are ignored; unknown names are logged and skipped
  4. File → Save Current Level
Add a new option to the case type
  1. Content Browser → /Game/Core/Blueprints/World/BP_WeaponCase_AssaultRifle → double-click
  2. Class Defaults → Case → SlotDefinitions → +
  3. SlotId → e.g. Holosight
  4. SocketName → the socket on the case mesh, or leave None and place it with Offset
  5. PickupClass → /Game/Core/Weapons/Pickups/Attachments/BP_Attach_Holosight
  6. PreviewMesh → the matching static mesh (or PreviewSkeletalMesh — assign one, never both)
  7. Compile + Save
If an item sits wrong in the foam the fix order is: (1) the slot's Offset transform — non-uniform scale is supported and expected; (2) OnCaseItemPreFinish to switch off the pickup's bLieFlat, which otherwise rotates tall meshes onto their side and fights the cutout; (3) OnCaseItemSpawned to shrink the item's interaction collider, since foam sockets sit ~11 cm apart. Only reach for bIgnoreInteractionTrace if PIE actually shows the case body swallowing the interact trace — it also makes the case transparent to bullets.

10 · Which attachments are available

Three independent gates. An attachment only reaches the player's gun if it clears all three.

GateSet whereFail behaviour
1 · Does the world offer it?Case FilledSlots, or a loose BP_Attach_* placed in the levelPlayer never finds it
2 · Does the held weapon accept the byte?Accepted*Options on the weapon's WeaponDataAssetPickup refuses — nothing mounts

11 · Pre-PIE checklist

  1. Navmesh rebuilt and green across the new area (press P)
  2. Every new spawn-zone origin projects to navmesh, and every spawn room has a route out
  3. Zones sit 15–45 m from the fight and are not visible from the main angles
  4. Every zone's ActivePhases matches the beat it should serve
  5. The scope volume's Z reaches the new floor
  6. Every phase you use has at least one valid composition
  7. MaxAlive exceeds the placed enemies in scope plus one full composition
  8. Placed squads have a shared SquadId; bIsolatedEncounter is off
  9. Every keycard grant id matches its door's RequiredKeycardId character for character
  10. Ammo grants use the category of the weapon the player will be holding there
  11. Wave zones the player can see are bWaveEligible = off
  12. Every GuaranteedSquads composition name exists in the effective phase config
  13. Objective ids are unique, and every chained marker has bActivateOnBeginPlay off
  14. Floors and ceilings block Visibility

12 · When nothing happens

No reinforcements arrive

In the order worth checking: the level never reached Loud · no zone is active for the current phase · every zone is visible to the player · every zone is outside 1500–4500 · zones sit outside the scope · zone origin is off navmesh · the phase's composition array is empty · the smallest composition will not fit under MaxAlive · placed enemies already fill MaxAlive · the director is in Peak or Relief.

Enemies appear in stupid places

Zones are in main rooms rather than service space · the box is too big and spills into geometry · the first sample points land inside cover · the spawn room is not actually off-sightline · SpawnDistanceMin is too low · a floor or ceiling is not blocking Visibility.

The wave never completes

Completion needs all squads spawned and all members dead. A member stuck off-navmesh or behind a closed door holds the wave open forever. Check GetWaveRemainingMembers in the logs, and confirm every wave-eligible zone has a real path into the fight.

A crate gives nothing

The ammo category does not match the held weapon · the stim count exceeded consumable capacity · bLooted was ticked on the instance · the interact volume is smaller than it looks and the trace is missing it.

An attachment will not mount

Its byte is not in the weapon's Accepted*Options. If it mounts but changes nothing, the byte's index in the *Attachments array is null — that is cosmetic-only by design, not a failure.
