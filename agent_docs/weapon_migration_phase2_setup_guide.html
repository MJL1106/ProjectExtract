The non-obvious bit
Adding the interface to BP_Item_Base in section A creates 18 empty stub methods. You also have to wire each one to call the kit's existing unprefixed twin (e.g. KitBeginFire calls existing BeginFire). Without this, kit weapons silent-fail.

For each broken call node

Targets: Reload, BeginFire, StopFire, Fire_HitScan, Inspect, Melee, ChangeFireMode, BurstFire, FinishFire, Trigger, SpawnAttachments, Unequip

  1. Right-click the broken node → Convert Call to Message
  2. If Convert Call to Message not available: delete the node → drag from the actor pin → search Kit<MethodName> → pick the (Message) variant → place
  3. Wire the actor ref (SpawnedItem or SpawnedItemRef) into the Target pin
  4. Reconnect input + exec pins on the new node
  5. Repeat for all ~8-12 broken nodes
  6. Compile clean
  7. File → Save

DRewire AC_ProceduralAnimation pose read

  1. Content Browser → /Game/ProceduralFPSKIT/Blueprints/Components/AC_ProceduralAnimation → double-click
  2. Open the Equip custom event graph
  3. Find the node reading WeaponActorRef → ProceduralValues → delete it
  4. Drag from WeaponActorRef → search Get Kit Procedural Values → pick the (Message) variant → place
  5. Wire WeaponActorRef into the Target pin
  6. Connect the returned DataAsset output to the existing Set ProceduralValues node input
  7. Compile
  8. File → Save

Pass criteria
Kit American Rifle behaves identically to pre-bridge. Output Log shows zero [KitWeapon] Warning lines. If you see "[KitWeapon] X has no WeaponData" or "KitWeaponPoseAsset is unassigned", the C++ safety net is firing — kit weapons should never hit that path unless their interface wrappers in section A are missing.

Next: equip our own weapon

After the bridge passes verification, this is how you slot a project-side weapon. The kit's character will drive it; our C++ runs the fire/reload/damage; kit's procedural arms animate it.

  1. Content Browser → right-click → Blueprint Class → search WeaponBase → pick → name BP_OurWeapon_Rifle (or similar)
  2. Open it → Class Defaults → WeaponData → assign or create a UWeaponDataAsset
  3. On the WeaponDataAsset → Kit Weapon Bridge → KitWeaponPoseAsset → assign /Game/ProceduralFPSKIT/Blueprints/Interactables/AmericanRifle/DT_RifleAnimationValues (free reuse of kit's existing rifle pose data)
  4. Assign the weapon skeletal mesh — kit's ik_hand_gun_N / ik_hand_l_N socket convention if you want iron sights working (skip if not)
  5. Compile + Save

Slot it into the character

  1. Open the test map's BP_FPCharacter instance
  2. Details → Class Defaults → PrimarySlot → BP_OurWeapon_Rifle (replace the kit rifle)
  3. File → Save Current Level
  4. PIE → equip → fire → confirm: ours fires (trace + damage + ammo via our code), arms animate via kit
