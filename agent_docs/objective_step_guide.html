Objective Steps

One placed actor per objective beat, chained together. Adding an objective is placing an actor and wiring two things — there is no C++ step any more. Property names are verbatim from the Details panel.

The whole idea

Each ObjectiveStep is one beat. It has a condition (what finishes it), optional side effects (what it does when it starts or finishes), and a NextStep pointer to the beat that follows. Drop actors, chain them, done.

The old ALevelObjectiveFlow is gone — DemoMap now runs on 13 of these.

Adding an objective

  1. Place Actors → search "ObjectiveStep" → drag into the level, near the thing it's about
  2. Details → Objective Step → Label → the HUD line, e.g. "Reach the server room"
  3. Details → Objective Step → Condition → pick from the dropdown, then fill the one payload field that appears
  4. Details → Objective Step → NextStep → the actor for the following beat
  5. On the first beat only: tick bIsEntryStep
  6. File → Save Current Level

StepId can be left None — it falls back to the actor's name. Only set it if you want a stable id for checkpoints or logs.

Two flags worth knowing. bRequiresAllContainers off means any one crate finishes the beat. bAnyInteractorCounts (on Interacted) is off by default, so only the player counts — turn it on if a companion looting the thing should also tick it off.
An unwired payload stalls the beat, loudly. An empty TrackedEnemies or TrackedContainers never completes — that's deliberate, so a mis-wire shouts in the log instead of silently skipping. Check the Output Log for LogObjectiveStep warnings after any wiring change.

Start a wave and wait for it on the same beat. Put StartDirectorWave on OnActivate and set the condition to WaveCompleted with the same WaveId. One actor, not three — and it's the shape that survives a checkpoint restart.

Markers — usually nothing to wire

Leave MarkerTarget empty. The marker location resolves in this order:

explicit MarkerTarget → derived anchor (EnemiesDead: the group's centroid at activation ContainerLooted: the nearest unlooted crate) → condition payload (the door / interactable / extractee it watches) → the step actor's own location

So a DoorOpened beat points at its door for free, and a ClearRoom beat holds the room instead of chasing the last surviving grunt.

bShowWorldMarkerOff = HUD text only, no world billboard, no off-screen arrow. Use for optional objectives.
bFreezeMarkerAtActivationPins the marker where it resolved at activation and ignores later movement. This is how "defend this ground" works — do not point it at the VIP, he walks off the spot you're telling the player to hold.
AreaAnchorOverrideForce the EnemiesDead anchor if the auto-centroid reads wrong. Leave zero otherwise.

Checkpoints

  1. Tick bIsCheckpoint on the beat you want to resume at
  2. Place a TargetPoint where the player should reappear
  3. Wire it to CheckpointSpawn

Entering a checkpoint beat records it and heals the companion once it's out of combat. On a restart the chain replays every earlier beat's end state, then activates the recorded beat and teleports the player and companion in.

What replaying an earlier beat restores is derived from its condition, so there's nothing extra to author:

DoorOpeneddoor opens
EnemiesDeadtracked enemies removed
ContainerLootedcrates marked searched, keycards re-granted (silently — no toast, no pickup SFX)
AcquireKeycardkeycard granted
ExtracteeRescuedVIP freed and armed
everything elsenothing — the beat just counts as done
Waves, level completions and route commands never replay. A restart can't re-fire a wave you already beat, end the level on load, or march the companion off from wherever it just teleported. This is enforced in code, not a flag you can tick.

Blueprint hooks

Activate() / Deactivate() / CompleteStep()All idempotent. CompleteStep on a beat that was never activated warns and refuses rather than firing out of order.
OnStepActivated / OnStepCompletedBind for bespoke scripting — VO, sequences, anything the side-effect list doesn't cover.

What the audit will tell you

At level load, in the Output Log under LogObjectiveStep:

  • a condition payload left unset, named per step and per array index
  • a NextStep pointing at itself, or a loop in the chain
  • zero entry steps, or two entry steps feeding one chain
  • duplicate StepIds in the level
  • a checkpoint beat with no CheckpointSpawn
  • a WaveCompleted beat after a checkpoint whose wave only an earlier beat starts — that combination would resume waiting on a wave that never runs

A clean level load prints one activation line and nothing else.
