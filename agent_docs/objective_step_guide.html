Adding the next beat

The chain currently ends at OS_12_UseLift. Two ways in:

A · Continue past the lift

  1. Place a new ObjectiveStep where the beat happens
  2. Details → Label → the HUD line
  3. Details → Condition → pick, then fill the one payload field that appears
  4. Select OS_12_UseLift → set its NextStep to your new actor
  5. File → Save Current Level

B · Insert into the middle

  1. Place the new step
  2. Set the previous step's NextStep to your new actor
  3. Set your new actor's NextStep to the step that used to follow
Nothing renumbers itself — the OS_07 style names are just labels for your benefit. If you insert between 7 and 8, name it OS_07b_… rather than renaming everything.

Markers — leave them alone

MarkerTarget is empty on all 13 actors and should stay that way. It resolves automatically:

derived anchor → EnemiesDead: the group's centroid, captured when the beat starts ContainerLooted: the nearest crate you haven't emptied condition payload → the door / lift / VIP the beat watches own location → for ReachLocation, AcquireKeycard, WaveCompleted, Manual

That's why step 4's marker holds the room instead of chasing the last grunt, and why the supplies marker walks you crate to crate.

bShowWorldMarkerOff on the supplies chain — text-only, no billboard, no off-screen arrow. That's the optional-objective look.
bFreezeMarkerAtActivationOn for step 11 only. Pins "defend this ground" where the rescue happened. Never point this at the VIP — he walks off the spot you're telling the player to hold.

Adding a checkpoint

  1. Tick bIsCheckpoint on the beat
  2. Place a TargetPoint where the player should reappear
  3. Wire it to CheckpointSpawn

A restart replays every earlier beat's end state — doors open, tracked enemies removed, crates marked searched with keycards re-granted silently, the VIP freed. Derived from each beat's own condition, so there's nothing extra to author.

Waves, level completions and route commands never replay. A restart can't re-fire the Room2Defence wave you already beat, end the level on load, or march the companion off from where it just teleported. Enforced in code — not a flag you can tick.

Before you playtest

  1. Exactly one actor has bIsEntryStep ticked (currently OS_01)
  2. Every new step's payload is wired — an empty TrackedEnemies or TrackedContainers never completes, on purpose
  3. Every new step has a NextStep, unless it genuinely ends a chain
  4. Any new keycard id matches its door's RequiredKeycardId character for character
  5. Output Log filtered to LogObjectiveStep shows one activation line and no warnings

The audit also catches: a NextStep pointing at itself, loops, duplicate StepIds, a checkpoint with no spawn point, and a WaveCompleted beat after a checkpoint whose wave only an earlier beat starts.

Two things about DemoMap worth fixing

There are no phase triggers in this level. The director never leaves its default mission phase, so the Infiltration and Extraction composition lists in DA_DirectorConfig never fire — only Objective ones do, plus step 11's wave which sets its own. If you want the level to ramp, place BP_PhaseTrigger boxes at the beats where it should, or add SetMissionPhase side effects to the steps you already have.
DA_DirectorConfig has two authoring slips: Flush is listed twice in ObjectiveConfig so its real odds are double what the weight says, and ShotgunPush in ExtractionConfig contains three Grunts and no Shotgun — the second entry's class was left as Grunt.
